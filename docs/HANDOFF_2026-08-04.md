## 2. The divergence, resolved

`origin/main` had been revamped independently (PR #1, 2026-07-27) toward the same
goal — "no fabricated data" — by the opposite route. Its environment had
biomedical APIs blocked (HTTP 403), so it *deleted* the fabricated signatures and
replaced them with a hand-encoded, hand-cited knowledge module. This branch
ingested and checksum-pinned the real sources instead.

You chose integration. What that meant concretely:

**Carried forward from `main`:**
- `clocks/phenoage.py` — the real published Levine coefficients. Registered
  alongside the 236 library clocks; no optional dependency.
- The ~1,000-line Streamlit redesign and `.streamlit/config.toml`.
- `knowledge/references.py` — 28 real papers — and the López-Otín hallmark
  vocabulary, now a **citation layer over measured data** rather than a data
  source.
- `clocks/service.py`'s `mortality_risk_10yr` field, which pairs exactly with
  PhenoAge. Its bare `except Exception` was narrowed to `ClockInputError`.
- `CanonicalGene.ortholog_group`, which also removed a `__dict__` hack.

**Deliberately not carried:**
- `knowledge/aging_knowledge.py`. Its hand-written per-gene evidence asserts what
  the ingested GEO panel now measures — and disagrees with it for CDKN2A.
  Shipping both would mean two answers to one question, one of them
  unfalsifiable.
- `main`'s `api/app.py`, which drops `/gene/{id}/signature`, `/geneset/signature`
  and `/studies`. Those are the endpoints that expose per-study effect sizes,
  which is the point of having them.
- `example_cohort_simulated.csv`, superseded by real NHANES.

⚠️ **A trap worth knowing.** Git merged `api/app.py`, `clocks/service.py`,
`idmap/resolver.py`, `conftest.py` and `test_clocks.py` *without conflict*,
because this branch had not touched the same lines — so it silently took `main`'s
versions wholesale, including the removal of three endpoints. "No conflict" is
not "no decision". Every file the merge touched was reviewed individually.

## 3. The clocks now run on real methylation

Full write-up: [`RESULTS_METHYLATION_CLOCKS.md`](RESULTS_METHYLATION_CLOCKS.md).

**New module `sources/methylation.py`** parses pinned GEO series matrices into
beta matrices plus age/sex/tissue metadata, restricted to control arms. Two
series pinned (~358 MB):

- **GSE64495** — 450K whole blood, n=106 controls, ages 2.3–73.7. Chosen because
  it ships **the authors' own Horvath-clock output per sample**, which allows a
  far stronger check than MAE against chronology: it isolates our wrapper from
  the clock's own accuracy.
- **GSE30870** — newborns vs nonagenarians, n=40. An extreme-contrast set; a clock
  that cannot separate cord blood from 90-year-old blood is broken in a way no
  correlation would reveal.

### Headline numbers

| Check | Result |
|---|---|
| biolearn Horvathv1 vs the authors' published values | **r = 0.9984, MAE 1.39 y** |
| pyaging horvath2013 vs the same | r = 0.9984, MAE 1.40 y |
| Horvath 2013 MAE vs chronological age | **3.61 y** (published: ~3.6) |
| Best clock overall (zhangblup) | 1.45 y, r = 0.9995 |
| Horvath on cord blood | **0.23 years** |
| Median MAE, GSE64495 / GSE30870 | 7.23 y / 17.45 y — the second is bimodal by design, so most clocks extrapolate |
| DNAmTL (telomere length) vs age | r = −0.967 — telomeres shorten; the sign is the check |

Two independent library implementations of Horvath land within 0.01 years of each
other. **That is what says the wrappers are correct rather than merely
non-crashing.**

72 of 236 on GSE64495 (and 58 of 200 on GSE30870) did not run, all explainable
and catalogued: clocks that are not methylation clocks at all (histone,
transcriptomic), EPIC-only clocks, clocks needing CpGs the series lacks, and the
`GPAge*` family.

### Why `GPAge*` cannot be fixed

**GPy requires numpy < 2; biolearn's `cvxpy` requires numpy ≥ 2.** Installing GPy
to gain 6 clocks was attempted, verified to break all 63 biolearn clocks, and
reverted. Do not retry until GPy supports numpy 2.

## 4. Everything is now real-data-backed

An audit swept the whole repo for generated, hand-written, or unsourced data.

| Was | Now |
|---|---|
| `idmap/data/genes.json` — 24 hand-picked genes | Generated by `etl/build_idmap.py` from every HAGR-curated gene plus its ortholog: **2,560 records, 1,835 groups**. The offline resolver could previously name 24 of the 1,880 genes in its own curated table |
| `idmap/data/anage.json` — 9 hand-transcribed lifespans | Parsed from the pinned AnAge release |
| `curated_knowledge.csv` had no symbols | Carries `symbol` and `species`, so browsing offline returns **1,880 genes** rather than the 22 that happened to resolve |
| PhenoAge had no data to run on | NHANES carries all nine PhenoAge markers out of the *already-pinned* XPORT files (MCV, WBC, ALP added at no download cost) → new dataset `clinical_nhanes_phenoage`, n=4,894. **r = 0.910 with chronological age, MAE 6.20 y** |

**The only synthetic table left is `clinical_synthetic_csd`**, and it is
deliberate: 720 subjects with critical slowing down planted by construction. It
is the only way to ask whether the estimator recovers an effect *known* to be
there, which no real dataset can answer. Its own dataset id, a `SYNTHETIC`
prefix, and a test that asserts it never merges with NHANES.

A design note worth preserving: the three PhenoAge-only markers went into a
**separate dataset id** rather than three more columns on `clinical_nhanes_slice`.
The resilience service infers its biomarker list by *excluding* known
non-biomarker columns, so widening the clinical table in place would have pulled
MCV, WBC and ALP into the health state and silently moved the published CSD
numbers.

## 5. Bugs found this session

Each was found by running real data, and each would have passed a stub.

1. **Symbol-built gene tables silently fail to join.** mygene resolves the symbol
   `CDKN1A` to `ENSG00000205643` — a copy on an alternative MHC haplotype
   scaffold — while Entrez `1026` resolves to the primary `ENSG00000124762`. The
   signature table is keyed on Entrez, so **p21 had twelve real contrasts and the
   API reported none.** `build_idmap` now resolves by Entrez wherever HAGR
   supplies one.
2. **Truncating a sorted alias list drops the tail.** Capping aliases at 12 lost
   `p16` from human CDKN2A, so the offline resolver answered "p16" with the mouse
   ortholog.
3. **The data version was not reproducible.** It hashed Parquet filenames and byte
   sizes; DuckDB writes a partitioned COPY in parallel, so two builds of identical
   data could report different versions. Now a content digest — which is what a
   data version was always supposed to mean.
4. **236 clock failures that were one data-prep bug.** Betas were handed over in
   the stored CpG-by-sample orientation, and `read_series` was deleting every CpG
   with any gap — including three Horvath coefficients. Both fixed; both pinned by
   tests.
5. **A test that passed only when you had not run `make data`.** It relied on the
   git-ignored full NHANES table being absent.

## 6. What to do next

### 6.1 Correlate age acceleration against resilience *(the reason this project exists)*

This is now unblocked and is the highest-value remaining work. Clock age minus
chronological age can be computed on real samples; the resilience metrics are
computed on real NHANES. **The cross-layer claim is still the one headline claim
with no evidence behind it in either direction.**

The obstacle is that the two live in different cohorts — GEO methylation samples
and NHANES participants are different people. Options, in increasing order of
effort: find a GEO series carrying both methylation and clinical chemistry; use
NHANES IV's DNA methylation subsample if accessible; or apply for a cohort that
has both.

### 6.2 Finish the GSE30870 sweep — 36 clocks short

GSE64495 is complete at 236 of 236. GSE30870 reached 200 of 236 before the runner
was stopped; the outstanding 36 are the slowest neural models. The runner writes
incrementally and resumes from `clock_results.csv`, so this is letting it run
rather than work. Nothing in the results depends on them.

### 6.3 recount3 or ARCHS4

Still the biggest single improvement to the signature panel: removes the
microarray-only limitation and the uncorrected cross-study processing
heterogeneity in one move. ARCHS4 is the lighter path — one HDF5, no R bridge.

### 6.4 Longitudinal resilience

`resilience/recovery.py` (AR(1) relaxation) remains implemented, tested, and never
run on real longitudinal data. NHANES III linked mortality files are free; ELSA /
SHARE / HRS need registration; UK Biobank is ideal and the federate-only adapter
already exists. This is what would resolve the CSD result's central caveat.

### 6.5 Smaller

- **Nested random effects by series.** 32 contrasts come from 27 GEO Series;
  paired array halves share subjects. `series_id` makes this checkable but the
  pooling does not account for it.
- **Re-add a sourced gene→hallmark mapping.** Dropped with `aging_knowledge.py`;
  `gene_report` keeps an empty `hallmarks` key so the shape is stable.
- **Survey weights.** `WTMEC2YR` is carried but not applied.
- **Ortholog mapping for HAGR** would recover the 2,276 non-mammalian assertions
  currently parsed and dropped.
- **`?library=` filter on `GET /v1/clocks`** — 240 entries is a lot unfiltered.

## 7. Gotchas

- **`GEROQUERY_ALLOW_NETWORK` is off by default.** Set it to `1` for anything
  touching an upstream.
- **Two interpreters, on purpose.** Python 3.14 runs the core suite; `.venv312`
  runs the clock libraries (`ecos`, a biolearn transitive dep, has no 3.14 wheel).
  Both staying green proves the optional tier is genuinely optional.
- **Do not install GPy.** See §3.
- **`signatures_full.csv` is gitignored; `signatures_curated.csv` is committed.**
  `LocalSignatureSource` prefers the full one when present, so a developer who has
  run `make data` sees different counts from CI. **Tests pin `prefer_full=False`
  for exactly this reason.**
- **`make signatures` ≈ 25 min cold**; `make idmap` needs network; both cache.
- **Never widen `nhanes.MARKER_MAP`.** The resilience service infers biomarkers by
  exclusion, so a new marker column silently joins the health state. Extra markers
  go in `PHENOAGE_ONLY_MARKER_MAP` and their own dataset id.
- **`get_registry()` memoizes.** Tests faking a clock library must reset
  `clocks.registry._REGISTRY`.
- **Live tests are excluded by default** (`-m 'not live'`). They are the only
  thing that catches upstream drift.
- **The GTEx age-bracket trap.** The open v2 API accepts `attributeSubset=ageBracket`
  and returns HTTP 200 with one undivided group. A live test pins this.

## 8. Reproducing

```bash
pip install -e ".[dev,ui]"          # add ",clocks" on Python 3.10-3.12

make data          # every upstream, verified   (~680 MB, ~30 min)
make idmap         # regenerate the derived identifier tables
make data-offline  # from the committed real samples (no network)
make ci            # ruff + mypy + 321 tests

GEROQUERY_ALLOW_NETWORK=1 pytest -m live
```
