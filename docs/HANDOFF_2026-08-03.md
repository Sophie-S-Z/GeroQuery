## 2. What was built

### 2.1 `geroquery/sources/geo.py` — the GEO DataSets adapter

**Why GEO DataSets (GDS) rather than GEO Series (GSE).** A GSE series matrix
carries age as free text — `age: 67`, `Age (yrs): 67`, `67y`, or buried in a
sample title, differently in every series. A GDS is the curator-built view: age
is a declared **subset variable** with named levels and explicit sample lists,
and the matrix ships with platform annotation joined, so every probe carries a
gene symbol and an Entrez id. Both fragile steps of GEO ingestion — deciding who
is old, and deciding what a probe measures — are answered by GEO's curators
rather than by a regex.

**The panel is rule-selected, not hand-picked.** This matters more than any
single dataset in it:

1. Query GEO DataSets for every record declaring an `age` subset variable in
   human or mouse → **189 records**.
2. Keep those yielding an adult young-vs-old contrast under `AGE_BANDS`
   (human young 18–40 y / old ≥60 y; mouse 2–8 mo / ≥18 mo). The middle is left
   empty on purpose.
3. Restrict to the control arm of every other subset variable (disease state,
   agent, genotype, protocol, stress, time). **A dataset whose confounder has no
   recognisable control level is dropped with a stated reason, not guessed at.**
4. Split rather than pool across tissue and cell-type variables.
5. Require ≥3 samples per group after all restrictions.

**31 datasets survive → 32 contrasts from 27 Series.** Change a rule and the
panel changes; nothing was selected because of what it showed. Resist adding or
dropping an accession by hand — that is exactly where selection bias enters.

### 2.2 `geroquery/harmonize/differential.py` — the statistics

Matrix → per-gene effect size. Three decisions are constants rather than inline
literals so they can be argued with:

- `LINEAR_SCALE_PERCENTILE` / `THRESHOLD` — the scale is **inferred from the
  data**, not trusted from GEO's declared `value_type` ("count" covers both raw
  MAS5 intensities and normalized values).
- `LOG_FLOOR` — background-subtracted intensities can be ≤0. Flooring compresses
  the bottom of the range; dropping those probes would silently delete the
  lowest-expressed genes, a worse bias.
- `MIN_GROUP_SIZE` — below 3 the pooled SD is too unstable to mean anything.

Probes collapse to genes by **MaxMean**. Multi-gene probes (`1029///1030`) are
dropped — a probe measuring two genes cannot be attributed to either.

`hedges_g_matrix` is a vectorized copy of `effect_size.hedges_g`, and
`test_matrix_hedges_g_matches_scalar_implementation` asserts they agree element
by element. **Without that test the fast copy would silently drift from the
reference.**

### 2.3 `geroquery/sources/hagr.py` — curated knowledge and interventions

Five HAGR releases. Two boundaries enforced in code rather than left to a reader:

- **Species.** GeroQuery models human and mouse. 2,276 of 5,029 assertions are
  yeast, worm, or fly; they are parsed, counted, and dropped rather than
  arriving in the store labelled as if mammalian.
- **Gene–intervention links.** DrugAge records no gene targets. The old table
  asserted `rapamycin → MTOR` by hand. **That edge was never in the data**, so
  drug interventions now ship with no linked genes, and only GenDR — which does
  record gene-level dependence — populates `linked_gene_ids`.

LongevityMap's **non-significant** entries are kept. A gene list built only from
positive associations cannot tell you that a gene was looked at and did not
replicate.

DrugAge aggregates to one record per compound × organism: median over the
**significant** experiments, with `n_experiments`. `lifespan_effect_pct = None`
means "tested, nothing significant" — deliberately not `0.0`, which would read
as a measured null effect of exactly zero.

### 2.4 `geroquery/idmap/bulk.py` — bulk identifier resolution

`MyGeneClient` caches one file per query, right for the request path and wrong
for an ETL resolving ~71k identifiers (≈50,000 sub-kilobyte files). This keeps
one consolidated map per species, reusing `normalize_hit` so record shape stays
identical. **Unresolvable ids are stored as `None`** — otherwise every rebuild
re-asks a free public service about the same thousands of failures.

Unlike the request path, a cache miss while offline is **fatal here**: a build
that silently dropped every unresolved gene would write a plausible-looking but
incomplete signature table.

### 2.5 `geroquery/etl/build_signatures.py` — the ETL

`make signatures`. ~313 MB download, ~25 min cold (dominated by SOFT parsing and
mygene lookups, both cached after). Writes:

| File | Committed? | Contents |
|---|---|---|
| `signatures_full.csv` | **no** (gitignored) | all 485,905 rows — reproducible from the manifest, so a committed copy would be an unverifiable second one |
| `signatures_curated.csv` | yes (5 MB) | 40,585 rows: curated aging genes **plus their cross-species orthologs**, both species |
| `studies.csv`, `curated_knowledge.csv`, `interventions.csv` | yes | small enough whole |

The ortholog step matters: HAGR curates mostly human genes, so without it the
committed slice would be almost entirely human and the mouse half of the panel
would be invisible to anyone who has not run `make data`.

## 3. Three real bugs, found only by running real data

A stub would have passed all three.

1. **`idmap/mygene.py` was writing other species' identifiers into the canonical
   id space.** mygene's `ensembl` field is sometimes a *list* of homology
   cross-references, so taking `[0]` gave mouse genes ids like `ENSFALG…`
   (collared flycatcher) and `ENSMPUG…` (ferret) — which then became the join key
   for that gene's signatures. Now filtered by the taxid's expected stable-id
   prefix, falling back to `ENTREZ:`. **This affected the live request path, not
   just the ETL.** Regression test:
   `test_ensembl_cross_reference_list_does_not_leak_another_species_id`.

2. **The download cache collided on URL basename.** HAGR serves both DrugAge and
   GenDR from a path ending `/dataset.zip`, so they shared one cache entry and
   whichever downloaded second overwrote the first. The checksum check turned
   that into a loud failure rather than a silent wrong answer — which is what it
   is for — but `fetch.cache_path` is now prefixed with the manifest key. Do not
   "simplify" that prefix away.

3. **`/v1/intervention/{name}` returned `matches[0]`.** With real DrugAge there is
   one record per organism, so asking about rapamycin returned the *C. elegans*
   result (+19.8%) instead of the mouse one (+13.0%) — a number about nematodes
   presented as the answer to a question about a drug. Now returns every
   organism, mammals first. **This is a breaking response-shape change**:
   `{"intervention": {...}}` → `{"name", "interventions": [...], "n", "linked_signatures"}`.

## 4. The scientific result

Full write-up: [`RESULTS_GEO_SIGNATURES.md`](RESULTS_GEO_SIGNATURES.md).

### 4.1 The panel is honest about its power

| | Human | Mouse |
|---|---|---|
| Genes with ≥3 contrasts | 20,850 | 21,133 |
| Median \|pooled *g*\| | 0.143 | 0.206 |
| Median I² | 21.0% | 38.2% |
| Genes at BH q<0.05 | 689 (3.3%) | 44 (0.2%) |

**Median 95% CI width: 0.84.** With 3–15 samples per study, a real effect of
*g* = 0.3 sits comfortably inside the interval of "nothing". This panel detects
large, consistent, cross-tissue effects and cannot rule out moderate ones. **A
null here means "not detected by this instrument", never "absent".**

### 4.2 p16 does not replicate

| Gene | pooled *g* (human) | 95% CI | k | I² | Verdict |
|---|---|---|---|---|---|
| CDKN1A (p21) | +1.07 | [+0.55, +1.59] | 12 | 67% | replicates |
| FOXO3 | +0.82 | [+0.43, +1.21] | 16 | 57% | replicates |
| SIRT1 | +0.58 | [+0.30, +0.86] | 12 | 5% | replicates |
| IGF1 | −0.53 | [−0.79, −0.27] | 16 | 13% | replicates |
| **CDKN2A (p16)** | **+0.07** | **[−0.20, +0.35]** | **14** | **14%** | **null** |
| LMNB1, TP53, TERT, GDF15, B2M | — | all span zero | — | — | null |

Fourteen contrasts, six up and eight down, low heterogeneity — the studies agree
with each other that there is nothing to see. **The synthetic slice this replaced
had p16 planted at *g* = +1.20, and the old API test asserted every direction was
"up". It passed.**

Two readings must be kept separate:

- **Partly an instrument problem, and a known one.** p16INK4a is expressed at very
  low levels in a small subpopulation of cells; the canonical results come from
  qPCR and single-cell assays, not bulk arrays. Several `CDKN2A` probes also
  cannot distinguish p16INK4a from p14ARF. Bulk microarray is close to the worst
  available instrument for this transcript.
- **Not only an instrument problem**, because the same instrument found p21,
  IGF1, the metallothioneins (MT1F, MT2A, MT1HL1 all up), and a coherent
  mitochondrial/OXPHOS decline (CYCS, UQCRFS1, DLAT) with tight intervals. Two
  well-replicated aging programmes fell out without being looked for. **The
  estimator works; p16 specifically is not measurable this way.**

Both facts are pinned as tests — one asserting the effect is found, one asserting
the CI still spans zero. The pair is what stops a null being waved away as a
broken estimator.

## 6. ⚠️ The blocker: `main` has diverged

**This is the most important section.**

While this session was running, a separate Claude Code cloud session merged
**PR #1** (`claude/geroquery-revamp-data-ui-459dby`, dated 2026-07-27) into
`origin/main`. That work pursued the *same goal* — "real data only, no fabricated
elements" — by a **different route**, because:

> **Network constraint discovered:** outbound access to biomedical APIs
> (mygene.info, NCBI) is policy-blocked in this environment (HTTP 403), so real
> data had to be encoded from established, citable knowledge rather than fetched
> live. — *remote `HANDOFF.md` §2*

So it **deleted** the fabricated signatures and replaced them with a hand-encoded,
cited knowledge module rather than ingesting anything.

### What each side has that the other does not

| | `origin/main` (PR #1, 2026-07-27) | `real-data-ingestion` (this session) |
|---|---|---|
| Signatures | `geroquery/knowledge/aging_knowledge.py` — 775 lines of curated, cited assertions. No per-study effect sizes | 485,905 measured effect sizes, 31 pinned GEO DataSets, real CIs and I² |
| Clinical | Synthetic cohort, honestly **renamed** `example_cohort_simulated.csv` | Real NHANES 2017–2018, n=4,895, SHA-256 pinned |
| Clocks | Real **Levine PhenoAge** implemented in `clocks/phenoage.py` | **236** biolearn + pyaging published clocks |
| Curated / interventions | Hand-curated with citations (`knowledge/references.py`) | Ingested HAGR releases, checksum-pinned |
| UI | **Ground-up Streamlit redesign** (1,116 lines), `.streamlit/config.toml`, plain-English analysis, figures + captions | Unchanged Streamlit; React labels updated only |
| Tests | 79 | 295 + 12 live |

**Each side has something the other genuinely needs.** The remote's UI redesign
and PhenoAge implementation are real work this branch does not contain. This
branch's ingested data and 236 clocks are real work the remote does not contain.

### Merge surface

`git merge` reports **no textual conflicts**, but that is misleading —
**23 files are touched by both sides**, including the whole core:

```
models.py  store/store.py  api/service.py  api/app.py  clocks/registry.py
clocks/service.py  sources/__init__.py  sources/local_fixture.py
etl/build_fixtures.py  ui/streamlit_app.py  conftest.py
tests/{test_api,test_clocks,test_sources,test_store}.py  README.md  pyproject.toml
```

The designs are **architecturally incompatible in places**: the remote makes
`geroquery/knowledge/` the source of truth and deletes `signatures.csv` from the
store path entirely; this branch keeps the partitioned-Parquet signature path and
fills it from GEO. An automatic merge would produce a tree that compiles and
fails, and would need hand-resolution of the store and service layers.

**Nothing has been overwritten.** This work is pushed to `real-data-ingestion`;
`main` is untouched.

### The three options

1. **Integrate — recommended.** Take this branch as the base (it is the larger
   superset on data, tests, and clocks) and port forward from `main`: the
   Streamlit redesign + `.streamlit/config.toml`, `clocks/phenoage.py`, and
   `knowledge/references.py` as a *citation layer over* the ingested data rather
   than a replacement for it. Estimated: the UI port is mostly mechanical; the
   store/service reconciliation is the real work.
2. **This branch wins.** Merge `real-data-ingestion` → `main`, accepting the loss
   of the UI redesign and PhenoAge until they are re-ported.
3. **`main` wins.** Keep the branch as a reference and re-apply only the
   ingestion pieces later.

**A force-push was deliberately not performed.** Option 3 is the only one where
this branch's work is set aside, and that should be your call, not an accident.

## 7. Next steps, prioritized

### 7.1 Resolve the divergence (blocking everything else)

See §6. Nothing below is worth starting until the base is settled.

### 7.2 Real methylation — close the clock loop *(highest leverage after §7.1)*

**236 clocks are wired and have never seen real data.** That is the largest
unexercised capability in the repo, and unlike most gaps it is *checkable*:
published MAEs exist, so running Horvath / Hannum / PhenoAge / DunedinPACE on a
GEO methylation series with age labels (**GSE40279**, Hannum's cohort, is the
obvious one) tells you whether the wrappers are correct rather than merely
non-crashing.

Most of the machinery transfers: `sources/fetch.py` verifies, `manifest.py` pins,
`sources/geo.py` parses SOFT. What is new is that methylation series are
GSE-only (no GDS), so the free-text age parsing this session deliberately avoided
has to be written — tractable for one or two specific series in a way it was not
for thirty.

Then compute age acceleration and correlate it against the resilience metrics.
**That cross-layer claim is the reason this project exists**, and it is currently
the only headline claim with no evidence behind it either way.

### 7.3 recount3 or ARCHS4 — fix the biggest signature confound

Removes limitation #1 (microarray-era only, no RNA-seq) and #5 (uncorrected
cross-study processing heterogeneity — 12 platforms, three decades of
normalization practice) in one move, and brings modern blood coverage. ARCHS4 is
the lighter path: a single HDF5, no R/Bioconductor bridge.

### 7.4 Longitudinal resilience

`resilience/recovery.py` (AR(1) relaxation) is implemented, tested, and has
**never run on real longitudinal data**. It is the module with the most
theoretical value and the least empirical exercise. NHANES III linked mortality
files are free and add a survival outcome; ELSA / SHARE / HRS need free
registration; UK Biobank is the ideal dataset and the federate-only adapter and
licence gate already exist.

This is what would resolve the central caveat of the CSD result — that NHANES is
cross-sectional, so no relaxation time is actually observed.

### 7.5 Smaller, worth doing

- **Nested random effects by series.** 32 contrasts come from 27 Series; paired
  array halves share subjects. `series_id` is carried on every study row so this
  is *checkable*, but the pooling does not yet account for it.
- **Survey weights.** `WTMEC2YR` is carried but not applied, so nothing is
  nationally representative. Applying it makes the CSD result a population claim.
- **Ortholog mapping for HAGR.** Would recover the 2,276 non-mammalian assertions
  currently parsed and dropped.
- **Pool multiple NHANES cycles** to get past the age-80 topcode, which compresses
  exactly the stratum where CSD should be strongest.
- **Repoint the Streamlit dashboard** at the real signature data (the React app is
  done). Moot if §6 option 1 is taken.
- **A `?library=` filter on `GET /v1/clocks`** — 239 entries is a lot to return
  unfiltered.

## 8. Gotchas for whoever picks this up

- **`GEROQUERY_ALLOW_NETWORK` is off by default.** Tests and CI are hermetic by
  construction. Set it to `1` for anything touching an upstream.
- **`signatures_full.csv` is gitignored; `signatures_curated.csv` is committed.**
  `LocalSignatureSource` prefers the full one when present, so a developer who
  has run `make data` sees different counts from CI. **Tests pin
  `prefer_full=False` for exactly this reason — do the same in any new test.**
- **`make signatures` takes ~25 min on a cold cache.** Both the SOFT parsing and
  the mygene lookups cache; a rebuild is minutes.
- **The clock tier needs Python 3.10–3.12.** `ecos`, a transitive biolearn
  dependency, has no 3.14 wheel. The core repo runs fine on 3.14. Two
  interpreters on purpose: both staying green is what proves the optional tier is
  genuinely optional.
- **`get_registry()` memoizes** a module-level registry. Tests that fake a clock
  library must reset `clocks.registry._REGISTRY`, or they pass alone and fail in
  a full run.
- **Live tests are excluded by default** (`-m 'not live'`). They are the only
  thing that catches upstream drift: GEO changing its FTP layout, HAGR renaming a
  file inside a zip, CDC moving a file, a checksum going stale.
- **The GTEx age-bracket trap.** The open v2 API *accepts*
  `attributeSubset=ageBracket` and returns HTTP 200 — with one undivided group.
  Donor age is dbGaP-controlled. A live test pins this so the claim is rechecked
  automatically rather than from memory.
- **HAGR releases are pinned by checksum**, so a HAGR update fails the build
  loudly rather than changing results silently. Intended — but it means the pins
  need periodic maintenance.
